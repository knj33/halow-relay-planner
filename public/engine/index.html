Relay Engine optional

A small native helper that downloads and resamples terrain in parallel on your own machine. The planner detects it automatically and falls back to the browser loader whenever it is not running.

What it does.
  • Streams Earth terrain tiles (Terrarium / SRTM and friends) with a thread pool, then resamples to the planning grid in C.
  • Reads Moon LOLA 118 m and Mars HRSC + MOLA 200 m GeoTIFF rows with HTTP range requests in parallel instead of one row at a time.
  • Returns a compact binary HRG1 grid over loopback. The browser still does the planning maths.
  • Binds to 127.0.0.1 only and rejects browser origins that are not on its allowlist.

1. Requirements

  • Linux on an x86-64-v3 capable CPU. AVX2 alone does not guarantee the full instruction set. Use the portable build below on other x86-64 CPUs.
  • A C compiler, make, and the libcurl + libpng development headers.
# Debian / Ubuntu
sudo apt install build-essential libcurl4-openssl-dev libpng-dev

# Fedora
sudo dnf install gcc make libcurl-devel libpng-devel

# Arch
sudo pacman -S base-devel curl libpng

2. Build and run

Download the two source files, or use the copy you already have in the project's native/ folder.

Download C source bundle · C source · Makefile

Download the source bundle, extract it, then run make && make install.

Installs to ~/.local/bin/relay-engine without root. Compilation targets x86-64-v3 by default; use make portable for baseline x86-64.

It listens on http://127.0.0.1:8765. Options: --port N, --threads N, and --origin URL (repeatable) to allow a hosted planner origin. 

curl http://127.0.0.1:8765/health
# {"ok":true,"name":"relay-engine","version":"0.1.0","arch":"x86_64","avx2":true,"threads":8,"pid":1234}
Using a hosted planner?

Add the site's origin when you start the engine, for example: ./relay-engine --origin https://planner.example.com. The development origins http://localhost:5173 and http://127.0.0.1:4173 are allowed by default.

3. Start it automatically (Linux, systemd user service)

mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/relay-engine.service <<'EOF'
[Unit]
Description=HaLow Relay Planner native terrain engine

[Service]
ExecStart=%h/.local/bin/relay-engine --origin https://planner.example.com
Restart=on-failure

[Install]
WantedBy=default.target
EOF
systemctl --user daemon-reload
systemctl --user enable --now relay-engine

Check status with systemctl --user status relay-engine. Nothing is exposed beyond loopback.

4. Browser extension (also optional)

The planner talks to the engine directly, so the extension is not required. A small Manifest V3 extension in the project's extensions/ folder can badge the engine status and mark the page as engine-aware. Download the extension and extract it. In Chromium, open chrome://extensions (Developer mode → Load unpacked) and select extensions/chromium. In Firefox, open about:debugging#/runtime/this-firefox → Load Temporary Add-on and pick extensions/firefox/manifest.json. The extension reports status; terrain requests go directly from the planner to the native engine.

Resources and larger areas

The engine uses up to 32 download workers by default, based on the online CPU count. Set --threads 4 to limit it. Native mode enables Earth areas up to 300 km and Moon and Mars areas up to 120 km, with finer grid budgets than the browser. Remote server speed still limits downloads. Larger grids do not increase physical radio range or resolve features smaller than the source elevation data.

Troubleshooting

For a hosted planner, your browser may ask for local or loopback network access. Allow that permission for this site, then press Detect again. The website continues using its browser loader if access is blocked. The extension does not bypass browser permissions.

“Not detected”

Confirm the engine is running: curl http://127.0.0.1:8765/health. Then press Detect in the planner's engine panel.

HTTP 403 origin not allowed

Restart the engine with --origin set to the exact origin shown in your browser's address bar, including scheme and port.

Build fails on AVX2

Use make portable to rebuild for baseline x86-64. Performance depends on the workload.

Moon or Mars loads slowly

The USGS mosaics are remote and row-addressed. Mars needs version 0.3.0 or later; an older engine is skipped for Mars. The engine parallelises the range requests; the first load is still network-bound.
